# Proposal

## Why

生成一轮应用目前「全凭运气」：没有时限、不能中断；执行中只有一句静态的「生成中…」，长任务卡住时使用者既不知道后台在推进什么、也没有退出的办法；上游限流或超时只会得到笼统的报错。首次进入是一块空白对话区，想看到效果必须先等一次实时生成，冷启动体验差。复杂需求被一次性塞给模型，容易撞上模型输出上限而生成不完整。界面虽然坚持零构建并可用，但视觉与交互停在最简形态：没有统一的间距、圆角、配色与字体层级，也没有暗色模式。生成出来的应用本身也常常缺一个完整的页面外壳（顶栏 / 侧边 / 卡片容器 / 响应式），看起来像「代码片段的堆叠」而不是一个成品。

这次变更就是把这五处体验补齐，让「描述需求 → 看到成品」这条路走得更稳、更快、更体面。

## What Changes

- **单轮生成时限**：新增可配置的单轮总时限（`CHAT_TIMEOUT_SECONDS`，默认 240 秒），计时从发起请求到本轮流结束；超时由服务端主动中止本轮，前端给出「生成失败」提示与**重试**按钮。
- **执行中的进度反馈**：生成过程中在界面上显示「正在生成第 N 行 · 已用 M 秒」，让使用者知道后台正在推进，而不是只有一句静态提示。
- **主动中断**：页面提供**中断**按钮，使用者可随时取消长任务；中断后给出明确反馈。
- **诚实报错**：模型调用统一包 try/catch，上游限流（429 等）与网络超时都如实上报，配合既有的错误分类给出可诊断的中文说明。
- **预置示例应用**：内置 3 至 4 个已完成的小应用 / 小游戏模板（如俄罗斯方块、贪吃蛇等）；使用者选择后，模板被复制进一个新会话的沙箱，**立即可预览**，不依赖实时生成。
- **分阶段生成**：提示词改为「先出骨架、再增量填充」——先写入 `index.html` 的结构与外壳，再逐个文件填充样式与脚本，避免一次性把整套应用塞给模型。
- **界面设计系统**：自建设计令牌（间距 / 圆角 / 配色 / 字体层级 / 阴影）与轻量组件样式，统一助手自身界面的视觉；支持**暗色模式**（跟随系统，可手动切换）。**保持零构建**：不引入 React / antd / Tailwind 与任何构建链。
- **生成应用的完整外壳**：提示词要求生成的应用具备完整的页面外壳——顶栏、侧边导航（按需）、卡片容器与响应式布局；示例模板同样遵循该约定。

## Capabilities

### New Capabilities

- `generation-execution-control`：单轮生成的时限与主动中止、执行中的进度反馈、失败后的重试入口，以及上游限流 / 超时的诚实报错。
- `example-apps`：预置示例应用的模板库，以及「选择即写入新会话沙箱并预览」的落点与接口。
- `web-ui-design-system`：助手自身界面的设计令牌与组件样式体系、暗色模式与响应式表现。

### Modified Capabilities

- `code-assistant-agent`：新增「分阶段生成（先骨架、再增量填充）」的生成规范，以及应用产物的「完整外壳」约定。
- `web-chat`：对话界面新增执行进度、失败重试与中断交互，并新增示例应用入口；界面表现统一到设计系统。
- `file-workspace`：新增「从模板目录把示例应用初始化进会话沙箱」的能力。

## Impact

- **代码**：`app/config.py` 新增单轮时限配置项（复用 `_positive_int()`）；`app/services/chat.py` 增加时限包裹、中断处理与限流识别；`app/api/chat.py` 传递时限并处理客户端断开；新增 `app/services/examples.py` 与 `app/api/examples.py`；`templates/examples/<示例 ID>/` 新增模板文件；`prompts/system.md` 增加分阶段生成与完整外壳两节；`web/index.html`、`web/styles.css`、`web/app.js` 增加进度 / 中断 / 重试 / 示例入口并重做视觉；`app/services/workspace.py` 扩展模板初始化能力；`app/main.py` 挂载示例路由。
- **接口**：新增 `GET /api/examples`（列出示例）与 `POST /api/examples/apply`（把某示例写入新会话沙箱）；`/api/chat` 保持既有请求 / 响应形态不变，仅在超时与限流情形下产出更明确的中文错误消息。
- **数据**：新增 `templates/examples/`（随版本库管理的静态模板）；示例被选用后产生一个真实会话与沙箱，落在既有 `data/sessions.db` 与 `data/workspace/` 之下，不引入新的落盘格式。
- **兼容性**：新增配置项有默认值，不填即可照常启动；既有会话、版本、分享、预览与下载行为不变。界面视觉有变化但操作入口与语义保持兼容（新增按钮，不删除既有入口）。
- **文档**：`README.md` 与 `docs/project-overview.md` 需同步补充时限与中断、示例应用、分阶段生成、设计系统与暗色模式、以及生成应用的完整外壳约定。
