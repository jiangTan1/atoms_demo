# Design

## Context

动机见 proposal.md 的 Why。本设计基于对当前实现的核实：

- 一轮对话的驱动点是 `app/services/chat.py` 的 `stream_frames()`：它 `async for` 迭代 `runner.run_async(...)`，把 ADK Event 交给 `FrameBuilder` 归一化，流结束后产出唯一一次完整帧与 `done` 帧。**这是加时限与处理中断的唯一收口点**。
- 接口层 `app/api/chat.py` 用 `StreamingResponse` 包装该协程，收尾时按沙箱指纹留档版本（`snapshot_if_changed`）。
- 错误分类已收敛为 `auth_error` / `network_error` / `upstream_error` 三类（`classify_failure()`），三类之外没有别的码，前端按 `code` + `message` 展示。
- 前端是无构建单页：`web/index.html` + `web/app.js` + `web/styles.css`，`fetch` 读取 SSE 流并按帧渲染；已有认证门控、顶栏、弹层与 401 集中处理。样式目前只有一组 `:root` 变量与手写组件样式，**没有暗色模式**。
- 会话与沙箱归属由登录态决定（`user:<用户名>`）；沙箱落在 `data/workspace/<会话>/`，配额为单文件 256 KB / 200 文件 / 10 MB，**足够容纳示例模板**（模板均为数十 KB 级的纯静态应用）。
- 「新建会话惰性创建」是既有约定：不预先落库，首次提问才创建。示例应用需要**立刻**有沙箱可预览，因此是一个有意引入的例外（见决策 6）。
- 提示词 `prompts/system.md` 是静态单例（`LlmAgent` 模块级单例），所有生成规范都写在其中；服务端无法在一次模型输出中做「切分」，因此分阶段生成只能靠提示词约束（见决策 7）。
- 项目现状：`SESSION_BACKEND=sqlite`，`data/` 已在 `.gitignore` 内，全量 pytest 258 项通过。

## Goals / Non-Goals

**Goals:**

- 单轮生成**有上限、可中断、可重试**，且执行过程中使用者能感知后台在推进。
- 首次进入即可**零等待看到成品**：预置示例应用选择即预览。
- 复杂需求不再一次性撞模型输出上限：**先骨架、再填充**。
- 助手自身界面具备**统一的设计令牌与暗色模式**，视觉与交互达到成熟组件库的观感。
- 生成的应用具备**完整页面外壳**，看起来是成品而不是片段堆叠。

**Non-Goals:**

- 不引入前端框架、组件库或构建链（不引入 React / antd / Tailwind / npm）。visual 向 antd 靠拢指的是**观感与规范**，不是依赖。
- 不把设计系统强加给**生成的应用**（示例模板遵循外壳约定，但不引用助手侧的设计令牌文件）。
- 不做服务端渲染、不做应用的服务端执行与校验。
- 不做真实百分比进度（服务端不知道本轮总输出量，无法给出可信的百分比）。
- 不改 ADK 层、不改会话落盘结构、不改版本 / 分享 / 预览 / 下载的既有语义。
- 不做示例应用的市场 / 画廊 / 上传，示例模板是**随版本库发布的内置集合**。

## Decisions

### 1. 单轮时限放在服务端，包住整个生成协程

- **做法**：在 `stream_frames()` 里用 `asyncio.timeout(settings.chat_timeout_seconds)` 包住 `runner.run_async(...)` 的迭代与收尾；超时（`TimeoutError`）时中止本轮，产出 `error` 帧（`code="upstream_error"`，消息明确为「本轮生成超过 N 秒已主动中止，可点重试重新生成」），随后照常产出 `done` 帧让前端收尾。时限值来自新增配置项 `CHAT_TIMEOUT_SECONDS`（默认 240，正整数，非法时启动失败并点名该项）。
- **理由**：只有服务端计时才能真正**中止**这一轮——前端断开只是不再读响应，模型请求与工具调用可能仍在后台空转占用资源。计时口径为「发起请求到本轮流结束」，与需求一致，也不跨模型调用累计。
- **备选**：只在前端计时并在超时后 `abort()` 请求（被排除：前端只是放弃读取，服务端不感知，资源继续被占用）；把时限做成每次模型调用的超时（被排除：多轮工具调用的总时长仍可能无界，且与「单轮总时限」的口径不符）。

### 2. 主动中断用「客户端断开 + 服务端取消」实现，不新增取消接口

- **做法**：前端用 `AbortController` 断开 `/api/chat` 的 `fetch`；服务端在生成协程被取消（`asyncio.CancelledError`）时，在 `finally` 里释放本轮资源并直接结束生成器，不再产出后续帧。前端依自己的「已中断」标记给出反馈（服务端不必回帧，因为连接已断）。
- **理由**：SSE 是单向流，客户端断开即是最自然的取消信号，`StreamingResponse` 会随之取消生成器；引入一个额外的 `POST /api/chat/cancel` 需要服务端维护「会话 → 进行中任务」的映射与并发安全，收益不成比例。
- **备选**：新增取消接口按会话取消（被排除：同一会话可能并无进行中任务，还要处理多任务与竞态，复杂度远超收益）；用 `reader.cancel()` 之外的 `EventSource.close()`（被排除：既有实现用 `fetch` + `ReadableStream`，不适合改回 `EventSource`）。

### 3. 超时与中断的收尾不自动留版本

- **做法**：只有「本轮正常跑完」才在收尾处比对指纹并留版本。超时与中断属于**未完成的本轮**，其收尾**不推进指纹状态、不产生版本**；沙箱里已落盘的部分内容保持原样，使用者可继续对话让智能体补齐，或用既有的「版本」入口回滚到上一版丢弃半成品。
- **理由**：一轮被中止时沙箱里往往是「写了一半」的应用，把它当成一个可分享 / 可回滚的版本会让版本列表混入不可用产物。而不改动沙箱也不现实（工具调用一旦成功就已经落盘），因此选择「保留现状但不记版本」——下一轮正常结束后指纹相比上次留档必然变化，届时留的是「半成品 + 补齐」的最终结果，符合直觉。
- **备选**：中止后也留版本（被排除：版本列表被半成品污染）；中止后回滚沙箱到本轮起点（被排除：需要在本轮开始时整目录快照，成本高、且抹掉了使用者可能想保留的中间产出）。

### 4. 进度反馈在前端本地计算，不新增进度帧

- **做法**：前端在消费文本增量时统计**已接收文本的行数**，并自本轮开始计时，在状态区显示「正在生成第 N 行 · 已用 M 秒」（定时器每 500ms 刷新一次 M）。不新增 SSE 帧类型。
- **理由**：服务端不知道本轮最终会输出多少，**给不出可信的百分比**；行数与耗时都是前端可观测的事实，零协议改动、零服务端状态，且对使用者的实际价值（判断是否卡死、要不要中断）已经足够。
- **备选**：新增 `progress` 帧由服务端下发百分比（被排除：百分比无法真实计算，下发一个假数字属于误导，与「诚实报错」的取向相反）；用已完成文件数作为进度（被排除：模型可能在最后才写文件，期间进度长期为 0，反而更像卡死）。

### 5. 超时与限流仍收口在三类错误码内，靠消息说清事实

- **做法**：**不新增错误码**。系统自身的 240 秒时限归入 `upstream_error`，消息明确写「本轮生成超过 N 秒已主动中止」；上游限流（HTTP 429 / `rate limit` / `too many requests` 等）同样归入 `upstream_error`，消息点明「上游限流」。前端对**任何** `error` 帧都在消息下方展示**重试**按钮。
- **理由**：项目硬约束要求错误收口为 `auth_error` / `network_error` / `upstream_error` 三类，新增第四类会破坏这个约定与既有测试与文档。而「诚实报错」的关键在于**消息如实、可诊断**，不在于码的数量：超时、限流、上游错误对使用者而言都是「这次没成，可以重试」，用同一类码承载不同消息即可；重试按钮也不该只在超时时出现。
- **备选**：新增 `timeout_error` 码（被排除：破坏三类收口，且前端处理路径与 `upstream_error` 完全相同）；超时后静默重试一次（被排除：使用者等更久且不知道发生过什么，与「诚实」相反）。

### 6. 示例应用：随版本库的静态模板目录 + 「选中即建会话写沙箱」

- **做法**：模板以静态文件随时间版本库发布在 `templates/examples/<示例 ID>/`（每个示例是一套可直接运行的 `index.html` + `style.css` + `app.js` 等），并在 `templates/examples/manifest.json`（或等价的服务端清单）中登记示例的 ID、名称与一句话描述。新增 `GET /api/examples` 列出示例，新增 `POST /api/examples/apply`（body 带示例 ID）——服务端**创建一个新的真实会话**，把该模板目录整体复制进新会话沙箱，返回 `session_id`；前端随即切换到该会话并刷新预览。
- **理由**：模板是「已经写好、已经验证过」的成品，复制进沙箱后即可用既有的预览 / 版本 / 分享 / 下载全链路，也能继续对话修改——这正是使用者要的「零等待看到东西，然后接着改」。让模板走沙箱而不是走一个独立的预览通道，避免了第二套预览与权限逻辑。
- **备选**：把示例做成前端的静态预览、不落沙箱（被排除：无法继续对话修改，也无法版本 / 分享 / 下载，是死的内容）；让模型在场复制 / 生成（被排除：正是要摆脱「依赖实时生成」）；把示例直接预置成每个新用户的默认会话（被排除：会污染历史会话列表，且并非人人都要）。
- **有意例外**：「新建会话惰性创建」约定在此被打破——选择示例时会立即创建真实会话（否则没有沙箱可写、没有会话可预览）。这是该约定**唯一的例外**，仅由 `POST /api/examples/apply` 触发。

### 7. 分阶段生成只改提示词，不改服务端流程

- **做法**：在 `prompts/system.md` 的「任务一：生成网页应用」下新增分阶段规范：**先骨架**——先用 `write_file` 写入 `index.html`（页面结构 + 外壳布局，样式与脚本先用相对路径挂上占位引用）；**再增量填充**——随后逐个文件写入 `style.css`、`app.js` 等，一次写一个文件、写完再写下一个，不要在同一轮里把全部代码堆进一次输出。同时保留既有「同一文件最终内容确定后只写一次」的约束。
- **理由**：输出上限是**模型侧**的约束（单次 function call 的参数大小受模型输出能力限制），服务端没有插手中途切分的手段；把「一次要塞多少」拆给提示词，是当前架构下唯一可行的落点。骨架优先还能让首批写入天然更小，降低第一刀就撞上限的概率。
- **备选**：服务端把复杂需求自动拆成多个子请求依次驱动模型（被排除：需要额外的编排、状态与二次意图识别，架构改动远超本需求）；由服务端检测「写入被截断」再让模型续写（被排除：截断通常表现为模型侧报错或参数非法，难以可靠区分「截断」与「模型本来就写少了」，属于猜）。

### 8. 完整外壳写在提示词的产物约定，并由示例模板做样例

- **做法**：在 `prompts/system.md` 的「应用产物约定」下补充外壳要求：生成的应用应当有完整的页面外观——**顶栏**（应用标题 / 主要操作）、按需的**侧边导航**、内容放在**卡片容器**里、整体**响应式**（窄屏不溢出、可正常操作）；并明确「不要求引入任何外部 CSS 框架，用应用自身的样式实现」。示例模板遵循同一约定，作为可参照的标杆。
- **理由**：外壳是「生成的应用看起来像成品」的关键，而它同样是模型侧行为，只能靠提示词约束；给一组真实模板做样例，比纯文字描述更能锚定预期。
- **备选**：把 shell 做成服务端注入的模板骨架（被排除：会与模型生成的内容打架，且应用类型差异大，硬骨架反而限制生成）；不写外壳约定、只做示例（被排除：使用者自己描述的应用仍会缺外壳，需求 5 未落地）。

### 9. 设计系统：CSS 变量令牌 + 轻量组件样式 + 主题切换

- **做法**：在 `web/styles.css` 用 `:root` 定义一套**设计令牌**——间距（如 `--space-1..8`）、圆角（`--radius-sm/md/lg`）、配色（品牌色、语义色、中性色阶、背景 / 表面 / 边框 / 文本）、字体层级（`--font-size-xs..xl` 与行高）、阴影（`--shadow-1/2/3`）；组件样式（按钮的主次形态与尺寸、输入、卡片、弹层、标签、状态提示）统一改用令牌，视觉规范向 antd 靠拢（8px 间距基准、中性灰阶、克制的品牌色、一致的圆角与阴影层级）。暗色模式：默认跟随系统（`@media (prefers-color-scheme: dark)` 覆盖令牌），并在顶栏提供手动切换（在 `<html>` 上设 `data-theme="dark|light"` 覆盖，选择记入 `localStorage`，读取失败时退回跟随系统）。**不引入任何前端依赖。**
- **理由**：令牌化是把「统一间距 / 圆角 / 配色 / 字体层级」变成可维护事实的唯一低本做法；纯 CSS 变量在零构建约束下完全够用。暗色模式靠覆盖同一组令牌实现，不需要为每个组件写第二套样式。
- **备选**：引入 Tailwind / antd（被排除：需要构建链或运行时，与「无前端构建」的既有取向直接冲突，且 TCS 体积与离线降级都会变复杂）；只做暗色模式不做令牌（被排除：无法满足「统一间距 / 圆角 / 配色 / 字体层级」）；用 `prefers-color-scheme` 单一来源、不做手动切换（被排除：使用环境不一定能改系统主题，手动切换是实际可达性需求）。
- **范围**：只作用于**助手自身界面**（认证页 + 对话页 + 各弹层）。生成的应用与示例模板不引用这些令牌文件（沙箱内的应用必须自包含）。

### 10. 示例路由的鉴权与错误口径

- **做法**：`GET /api/examples` 与 `POST /api/examples/apply` 都要求登录（复用 `Depends(current_user)`）。未知示例 ID 返回 404 与中文提示；模板目录缺失或复制失败返回 500 与中文提示（并保证不留下半初始化的会话沙箱）。返回的 `session_id` 归属当前登录用户。
- **理由**：示例虽不含私有数据，但「选择即建会话」会写入使用者名下的沙箱，属于已登录才能做的事；两条路由放在鉴权之后与既有接口一致，也让 401 集中处理自然生效。复制失败时的清理要求，避免使用者进到一个「看起来有会话但沙箱是空的」的状态。
- **备选**：示例列表免登录（被排除：无需如此，且会让路由白名单与 401 集中处理多一条特例）；不校验而直接把模板 ID 当路径拼接（被排除：必须做路径校验，模板 ID 只允许命中清单内的既定项）。

## Risks / Trade-offs

- [服务端时限与工具调用的交互：超时可能恰好发生在某次 `write_file` 成功之后] → 本轮不产生版本（决策 3），沙箱保留已落盘内容；前端明确提示「已中止、可重试」，并把「可回滚到上一版本」的入口保持在原位。
- [客户端断开（中断）时服务端可能无法立刻感知，模型请求要等下一次取消检查点才真正停下] → `StreamingResponse` 取消生成器会在下一个 await 点生效，属于可接受的延迟；不做轮询式强制终止，避免引入额外的并发管理。
- [中断与超时都不留版本，可能让使用者误以为沙箱没被改过] → 中断 / 超时后前端刷新预览（呈现实际沙箱内容）并在状态区说明「本轮未完成，已写入的部分仍在沙箱中」。
- [示例模板是手工维护的静态内容，可能随界面约定变化而过时] → 模板遵循与提示词相同的「完整外壳」约定（决策 8），并在测试中覆盖「每个示例都含入口 `index.html` 且能被预览路由正常提供」。
- [新增配置项 `CHAT_TIMEOUT_SECONDS` 需要与 `proxy_read_timeout` 协调] → 默认 240 秒小于部署样例的 `proxy_read_timeout 300s`，由应用先中止、代理不会抢先断开（余量 60s，后续要再上调时限需同步加大代理读超时）；文档中说明「时限应小于反向代理的读超时」，避免代理先断开而掩盖真实原因。
- [暗色模式与手动切换引入额外的状态，可能在某些浏览器 / 隐私模式下不可用] → `localStorage` 读写包 try/catch，失败时静默退回「跟随系统」；不因此白屏或报错。
- [设计系统重做样式有回归风险（既有靠 `hidden` 与 `display` 的坑此前踩过）] → 重做时保持既有类名与结构不变，只替换令牌与视觉规则；对 `[hidden]` 相关的显式 `display` 覆盖逐条保留，并做浏览器逐项验收。

## Migration Plan

1. 配置层：在 `app/config.py` 增加 `CHAT_TIMEOUT_SECONDS`（默认 240，复用 `_positive_int()`），在 `.env.example` 补充该项与中文注释。
2. 服务层：在 `app/services/chat.py` 用 `asyncio.timeout` 包住生成协程，处理超时与 `CancelledError`，识别上游限流并完善消息；保证超时 / 中断路径不产出多余的完整帧与 `done` 帧语义混乱。
3. 接口层：`app/api/chat.py` 传递时限并在超时 / 中断时跳过版本留档（决策 3）。
4. 示例应用：新增 `templates/examples/<示例 ID>/` 与清单，新增 `app/services/examples.py`（模板校验、沙箱初始化）与 `app/api/examples.py`（列表与选用），在 `app/main.py` 挂载；`app/services/workspace.py` 增加「按模板目录初始化沙箱」的能力。
5. 提示词：`prompts/system.md` 增加「分阶段生成」与「完整外壳」两节；示例模板按同一约定编写。

回滚：本变更是「新增配置项 + 服务层时限包裹 + 新增示例路由与模板 + 提示词两节 + 前端视觉与交互」。回退时删除 `templates/examples/` 与新增的示例服务 / 路由、移出 `asyncio.timeout` 包裹、还原 `prompts/system.md` 与原 `web/styles.css` 即可回到变更前形态；已由示例产生的会话与沙箱是普通会话，无需迁移。
