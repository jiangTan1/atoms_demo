# Spec Delta

## MODIFIED Requirements

### Requirement: 应用产物约定
生成的应用 SHALL 包含入口文件 `index.html`；页面引用的样式、脚本与其他资源 SHALL 使用相对路径放在沙箱内，使整个应用在沙箱目录这一路径空间下即可运行。生成的应用 SHALL 具备完整的页面外壳——包含顶栏，内容置于卡片容器中，整体响应式适配窄屏；按应用类型按需提供侧边导航。外壳 SHALL 由应用自身的样式实现，SHALL NOT 依赖任何外部 CSS 框架。

#### Scenario: 入口文件存在
- **WHEN** 智能体为某会话生成或修改应用
- **THEN** 沙箱内存在入口文件 `index.html`

#### Scenario: 资源以相对路径引用
- **WHEN** 应用包含独立的样式表或脚本
- **THEN** 入口页面以相对路径引用它们，且这些文件位于沙箱内被引用到的位置

#### Scenario: 不引用沙箱外资源
- **WHEN** 生成的应用需要样式或脚本
- **THEN** 这些资源落在会话沙箱内，不依赖沙箱之外的文件才能运行

#### Scenario: 具备完整页面外壳
- **WHEN** 智能体生成一个网页应用
- **THEN** 该应用呈现完整的页面外观：有顶栏与卡片式内容容器，窄屏下布局自适应且不溢出

#### Scenario: 外壳不依赖外部框架
- **WHEN** 应用具备顶栏、卡片容器与响应式布局
- **THEN** 这些效果由应用自身的样式实现，不依赖外部 CSS 框架或构建步骤

## ADDED Requirements

### Requirement: 分阶段生成
智能体生成网页应用时 SHALL 采用「先出骨架、再增量填充」的方式：先用文件工具写入 `index.html` 的页面结构与外壳，再逐次写入样式、脚本等配套文件，一次写入一个文件；SHALL NOT 在同一轮里一次性把整套应用的代码堆进单次输出。

#### Scenario: 先写骨架
- **WHEN** 智能体开始生成一个网页应用
- **THEN** 先写入 `index.html`，给出页面结构与外壳布局，并以相对路径引用后续将写入的样式与脚本

#### Scenario: 再增量填充
- **WHEN** 骨架已写入
- **THEN** 智能体逐个文件写入样式与脚本，一次写入一个文件，而不是把全部代码一次性输出

#### Scenario: 单文件一次写定
- **WHEN** 某个文件的最终内容已确定
- **THEN** 该文件只被写入一次，不在同一轮里反复覆盖

#### Scenario: 复杂需求不一次性塞入
- **WHEN** 使用者的需求较为复杂（依赖多、功能多）
- **THEN** 智能体按骨架与逐个文件的方式分批写入，避免单次输出超出模型能力而生成不完整
