# Spec Delta

## Purpose

为助手自身的界面建立一套统一、可维护的视觉规范：以设计令牌统一间距、圆角、配色与字体层级，组件样式遵循一致的形态；支持暗色模式与窄屏响应式，使界面的观感与交互达到成熟组件库的水准，同时**保持零构建、不引入前端框架与组件库**。

## ADDED Requirements

### Requirement: 设计令牌
助手自身界面的样式 SHALL 基于一套集中定义的设计令牌构建，令牌 SHALL 至少覆盖间距、圆角、配色（含品牌色与语义色）与字体层级；界面中的组件样式 SHALL 使用这些令牌而不是各自散落的字面量，从而使间距、圆角、配色与字体层级在整站保持一致。

#### Scenario: 间距与圆角一致
- **WHEN** 界面中的不同组件（按钮、输入、卡片、弹层）使用间距与圆角
- **THEN** 它们取自同一组令牌，不同组件之间的间距与圆角无随意差异

#### Scenario: 字体层级一致
- **WHEN** 界面呈现标题、正文与辅助文字
- **THEN** 各级文字的字号与行高取自同一组令牌，层级关系清晰且全站一致

#### Scenario: 配色一致
- **WHEN** 界面呈现品牌色、语义色（成功 / 警告 / 危险）与中性色
- **THEN** 这些颜色取自同一组令牌，同类语义在全站使用同一颜色

### Requirement: 暗色模式
助手自身界面 SHALL 支持暗色模式：默认跟随系统偏好，并 SHALL 提供手动切换；使用者在暗色与浅色之间切换时，界面的文字、背景、边框与语义色 SHALL 保持可读与对比度充分。手动选择 SHALL 被记住，无法持久化时 SHALL 静默退回跟随系统而不是报错或白屏。

#### Scenario: 跟随系统偏好
- **WHEN** 使用者的系统偏好为暗色且未手动指定主题
- **THEN** 界面以暗色呈现

#### Scenario: 手动切换主题
- **WHEN** 使用者手动切换主题
- **THEN** 界面立即按所选主题呈现，且在后续访问中保持该选择

#### Scenario: 无法记住选择
- **WHEN** 浏览器环境不允许持久化主题选择
- **THEN** 界面退回跟随系统偏好，不出现报错或空白

### Requirement: 响应式表现
助手自身界面 SHALL 在窄屏下保持可用：布局 SHALL 自适应排布，控件与文字 SHALL NOT 溢出或被裁切，主要操作 SHALL 仍可触达。

#### Scenario: 窄屏布局自适应
- **WHEN** 使用者在窄屏下使用对话界面
- **THEN** 对话区与预览区按可用的排布方式呈现，不出现内容溢出到视口之外

#### Scenario: 控件不被裁切
- **WHEN** 使用者在窄屏下查看顶栏与弹层
- **THEN** 按钮、输入与提示文字完整可见，主要操作可点击

### Requirement: 保持零构建
助手自身界面 SHALL 继续以原生 HTML / CSS / JavaScript 直接提供，SHALL NOT 引入任何需要构建步骤或运行时依赖的前端框架与组件库；设计系统的实现 SHALL 仅使用浏览器原生能力。

#### Scenario: 无需构建即可运行
- **WHEN** 部署本变更后的服务
- **THEN** 前端资源无需任何构建步骤即可由服务直接提供，页面正常加载

#### Scenario: 不引入框架依赖
- **WHEN** 检查前端资源
- **THEN** 不存在对前端框架或组件库的运行时依赖

### Requirement: 降级不白屏
外部资源（如 CDN 上的 Markdown / 高亮 / 清洗库）不可达时，界面 SHALL 退化为纯文本展示并保持对话与复制可用，SHALL NOT 出现白屏；样式与主题 SHALL 在无外部资源时依然生效。

#### Scenario: CDN 不可达
- **WHEN** 页面引用的外部资源加载失败
- **THEN** 对话内容以纯文本形式呈现，页面样式与主题仍然生效，界面可正常使用

#### Scenario: 主题不依赖外部资源
- **WHEN** 外部资源不可达时使用者切换主题
- **THEN** 主题切换仍然生效
