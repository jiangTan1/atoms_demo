# Proposal

## Why

上一个变更（`add-code-assistant-agent`）交付的对话是「一次性」的：会话默认放在内存里，页面一刷新当前对话就消失，使用者没法回看昨天的结论；同时智能体只覆盖生成、解释、重构三类任务，当使用者手里已经有一段可疑代码时，无法请它帮忙定位问题。本变更为这两个实际使用缺口补齐能力：让对话落盘并可回看，让智能体能够做缺陷排查。

## What Changes

- 会话落盘：`SESSION_BACKEND` 默认值由 `memory` 改为 `sqlite`，对话事件写入 `data/sessions.db`，刷新页面乃至重启服务后仍能找回历史对话。
- 新增历史会话列表接口 `GET /api/sessions`：返回会话标识、标题、最近更新时间与消息数，按最近更新时间倒序、限量返回。
- 新增历史消息接口 `GET /api/sessions/{session_id}/messages`：按时间顺序还原该会话的多轮消息。
- 新增事件→消息还原逻辑：把 ADK 会话事件归一化为「角色 + 文本」的可渲染消息，跳过流式中间态与纯错误事件。
- 前端会话恢复：用 `localStorage` 记住当前 `session_id`，页面加载时自动载入该会话历史；顶栏新增「历史会话」面板，可浏览并一键切换；新建会话后刷新列表。
- 提示词新增第四类任务：**缺陷排查与优化点识别**（分级问题清单 + 定位 + 触发条件 + 修复后完整代码；无问题须如实说明，不得凑数），并把「只处理三类任务」更新为四类。
- **非目标（Non-goals）**：本版不做代码执行/沙箱运行、不做静态分析器或编译级检查（缺陷识别完全依赖提示词与模型判断）、不做会话重命名与删除、不做登录鉴权与多用户隔离（仍使用固定 `web-user`）。原变更 proposal 中「不做报错调试排查能力」的非目标在本变更中取消。

## Capabilities

### New Capabilities

- `session-history`: 会话的持久化与历史还原能力，包括对话落盘存储、历史会话列表查询、历史消息读取，以及网页端的自动恢复与会话切换。

### Modified Capabilities

- `code-assistant-agent`: 任务范围由三类扩展为四类，新增「缺陷排查与优化点识别」，并明确该类任务由自然语言触发、不新增界面控件。

## Impact

- **配置**：`.env` 与 `.env.example` 中 `SESSION_BACKEND` 的默认值与说明改为 `sqlite`；`app/config.py` 的默认取值同步。
- **接口**：新增两个只读端点；`POST /api/chat`、`POST /api/sessions` 的请求与响应协议保持不变，前端无需改动调用方式。
- **数据**：新增本地 SQLite 文件 `data/sessions.db`（已在 `.gitignore` 中忽略），不引入迁移框架；由内存后端切到 SQLite 后，此前仅存在于内存的会话不会迁移。
- **前端**：`web/index.html` 增加历史会话面板，`web/app.js` 增加 localStorage 与历史加载逻辑，不新增第三方依赖。
- **提示词**：`prompts/system.md` 增加第四类任务章节与输出结构约束。
- **风险**：会话列表的标题与消息数需逐会话读取（N+1 次查询），故列表按最近更新倒序并限制条数；`localStorage` 中记录的会话可能已在服务端失效，需回退为新建会话。
