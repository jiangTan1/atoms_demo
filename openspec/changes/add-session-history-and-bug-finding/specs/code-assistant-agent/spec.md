# Spec Delta

## Purpose

在原三类任务（代码生成、代码解释、重构与优化）的基础上，补充「缺陷排查与优化点识别」能力：使用者除了让助手写代码，还能把手里已有的代码交给它做问题定位与改进建议。

## ADDED Requirements

### Requirement: 缺陷排查与优化点识别
智能体 SHALL 在收到「这段代码有什么问题」类请求时进入缺陷排查模式，输出问题清单与修复后的完整代码；问题清单 SHALL 逐条标注严重程度、问题定位与触发条件，且 SHALL NOT 编造不存在的问题。

#### Scenario: 定位缺陷
- **WHEN** 使用者提交一段存在缺陷的代码并询问其中有什么问题
- **THEN** 智能体给出问题清单，逐条说明问题位置、问题类型、严重程度、触发条件与后果

#### Scenario: 提供修复结果
- **WHEN** 智能体识别出至少一个需要修复的问题
- **THEN** 智能体给出修复后的完整代码（而非零散补丁片段），并以标注语言的 Markdown 代码块给出

#### Scenario: 代码无缺陷
- **WHEN** 使用者提交的代码未发现实质性问题
- **THEN** 智能体如实说明未发现缺陷，最多给出少量可选的优化点，不得为凑数而编造问题

#### Scenario: 仅需优化建议
- **WHEN** 使用者提交的代码功能正确但存在可改进之处（性能、可读性、健壮性、安全性）
- **THEN** 智能体以优化点清单的形式给出建议，并说明每项的收益与适用前提

### Requirement: 缺陷排查的触发方式
智能体 SHALL 将缺陷排查与既有的代码生成、代码解释、重构优化并列为可处理任务；当使用者以自然语言提出排查请求时，系统 SHALL 直接进入排查模式，SHALL NOT 要求使用者先切换模式或点击额外控件。

#### Scenario: 自然语言触发排查
- **WHEN** 使用者粘贴代码并附带「有什么问题」「帮我找 bug」「哪里会出错」等表述
- **THEN** 智能体直接按缺陷排查模式作答，界面无需任何额外操作

#### Scenario: 超出职责范围的请求
- **WHEN** 使用者的请求与代码无关（如闲聊）
- **THEN** 智能体简短说明职责范围，并把话题引导回代码
