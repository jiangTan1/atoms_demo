# Proposal

## Why

当前系统里不存在「谁在访问」这件事：全站无鉴权，任何拿到地址的人都能消耗模型额度；`/api/workspace/download` 只按会话标识查询，会话 ID 可被枚举，他人沙箱里的项目文件可被下载；而 `user_id` 是请求体里由客户端自报的字段，服务端无条件信任——这意味着「这段会话、这些文件属于谁」在系统里根本没有依据。要把它当成一个可以对外提供服务的东西（哪怕只是内网演示），第一步必须是把访问者确定下来，再让会话与文件沙箱有真正的归属。

## What Changes

- 新增账号体系：用户记录（用户名、密码哈希、角色、创建时间）与服务端登录态记录；密码一律以加盐哈希保存，不存明文。
- 页面初始即停在认证界面：三个入口按钮（注册 / 修改密码 / 登录）+ 用户名与密码输入框 + 登录与取消按钮；未登录不进入对话界面。
- 注册：填写用户名与密码，两者均为 3–20 个字符；注册者一律为普通用户；普通用户总数上限 99（默认管理员 `root` 不占该名额）。
- 登录：服务端保存并校验用户名与密码；成功后下发 HttpOnly 会话 Cookie，有效期 1 天；提供退出登录。
- 修改密码：使用者填写原密码与新密码，校验通过后更新；改密后立即失效该用户的其他登录态。
- 初始化默认管理员 `root` / `root`：首次启动且账号库为空时创建，已存在则不覆盖。
- 管理员可新增用户、重置任意用户的密码、删除用户；`root` 自身不可被删除；用户名注册后不可修改（避免历史会话与沙箱的归属错乱）。
- **BREAKING**：所有既有 `/api/*` 接口改为要求登录，未登录返回 401 与中文提示；`user_id` 不再由客户端传入，一律取自登录态。
- 会话历史与文件沙箱按登录用户隔离：使用者只能列出、切换、下载自己的会话与项目。
- 前端新增认证界面与登录态处理（含登录失效后回到认证界面）；README 补充认证相关配置与使用说明。

## Capabilities

### New Capabilities

- `user-accounts`: 账号数据模型与存储、用户名与密码的格式约束、密码的加盐哈希与校验、注册（含普通用户 99 个上限）、修改自己的密码、默认管理员 `root` 的初始化，以及管理员的用户管理（新增 / 重置密码 / 删除）。
- `access-control`: 登录与登出、登录态的建立与过期、密码修改后的登录态失效、受保护接口的鉴权要求与未登录时的拒绝行为，以及会话与文件沙箱按登录用户的归属规则。

### Modified Capabilities

- `web-chat`: 页面初始展示认证界面（三个入口按钮 + 用户名密码输入框 + 登录 / 取消），未登录不进入对话界面；登录后顶栏展示当前用户名并提供退出登录。
- `session-history`: 会话列表与历史消息的查询范围改为按登录用户隔离，`user_id` 由登录态决定而不由客户端指定；既有匿名会话不再展示。
- `file-workspace`: 打包下载接口必须校验目标会话属于当前登录用户，拒绝下载他人会话的沙箱内容。

## Impact

- **代码**：`app/config.py`（认证相关配置项与启动期校验）、`app/services/`（新增账号与登录态服务）、`app/api/`（新增认证接口；`chat` / `sessions` / `workspace` 增加鉴权）、`app/schemas.py`（移除客户端 `user_id` 字段，新增认证相关模型）、`web/`（认证界面与登录态处理）。
- **数据**：`data/sessions.db` 新增用户表与登录态表；既有匿名会话与其沙箱按用户隔离后不再可见（不迁移，保留在库中）。
- **依赖**：不新增第三方依赖，密码哈希使用标准库 `hashlib.pbkdf2_hmac`。
- **对外行为**：**BREAKING** —— 所有既有 `/api/*` 调用在未登录时返回 401；请求中的 `user_id` 字段被移除。
- **部署与安全**：登录态 Cookie 在无 HTTPS 时明文传输，需与既有部署章节的 HTTPS 配置配套；默认口令 `root` / `root` 与 3 字符的密码下限都属于演示级取舍，须写入已知限制并在上线前修改。
