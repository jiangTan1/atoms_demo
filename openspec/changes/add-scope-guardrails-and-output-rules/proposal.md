# Proposal

## Why

现有智能体对「职责范围」的处理只有一句「超出范围就简短说明并引导回代码」，缺少三类实际需要的边界控制：

- **领域边界没有固定说法**：闲聊或非编程咨询的回答方式随模型发挥，措辞与是否作答都不稳定。
- **法规与安全风险没有约束**：使用者询问公开网络服务、政府网站等的漏洞或利用代码时，提示词没有拒答要求，存在合规与安全风险。
- **澄清没有次数上限**：信息不足时智能体会追问，但可以无限反复，使用者可能陷入「问了半天仍做不了事」的空转。

输出侧也缺少两项直接影响可用性的能力：代码块只能整块复制，不能另存为文件；界面不显示当前会话标识，调试与问题定位时无法确认自己正在哪个会话里。

## What Changes

- **领域范围限定**：判定为非代码/编程领域的请求不尝试作答，固定回复「我是代码和编程领域的智能体，暂时不能回复其他领域的问题，请尝试和我讨论代码和编程领域的问题吧，谢谢！」。
- **法规与安全风险拒答**：属于编程领域但涉及法规/安全风险（典型如公开网络服务、政府或事业单位网站的漏洞探测、利用与攻击代码）时，不提供具体内容或代码，仅说明受法规与安全限制无法回复，并引导回常规编程话题。
- **澄清追问与次数上限**：意图不明时允许追问或给出选项供选择；追问轮次由服务端统计并注入，连续 5 轮仍无法明确时由服务端直接返回固定结束语，不再继续追问。
- **代码块另存为**：代码块工具区在「复制」旁新增「另存为」按钮，按代码块语言自动推断扩展名并下载为文件。
- **会话标识展示**：页面显示当前会话 ID，便于调试与问题定位。
- **表格输出偏好**：涉及多个对象对比或多个并列说明时，优先以 Markdown 表格呈现。
- **非目标（Non-goals）**：不做登录鉴权与用户权限体系；不做敏感内容的自动分类器或内容审核服务（法规风险判断完全依赖模型与提示词）；不做追问轮次的可视化统计面板；不做代码块文件名的手工编辑与保存路径选择。

## Capabilities

### New Capabilities

（无新增能力，均由既有能力扩展。）

### Modified Capabilities

- `code-assistant-agent`：新增「领域范围限定」「法规与安全风险拒答」「澄清追问与次数上限」三类意图处理规则，以及「对比与并列内容用表格」的输出偏好。
- `web-chat`：代码块新增「另存为文件」操作；界面新增当前会话标识展示。

## Impact

- **配置**：无新增配置项。
- **提示词**：`prompts/system.md` 新增意图识别与边界章节（领域限定、法规风险、澄清标记协议与追问上限）和表格输出偏好；Agent 的 instruction 拼装方式不变。
- **接口**：`POST /api/chat` 的请求与响应协议不变；服务端沿用在用户消息前追加内部标记的既有做法，把澄清轮次一并注入；达到上限时短路返回固定结束语。
- **服务层**：`app/services/chat.py` 新增澄清轮次推导、澄清标记过滤与历史前缀还原的扩展；`app/api/chat.py` 传入轮次并处理上限分支。
- **前端**：`web/app.js` 新增另存为按钮与文件名推断、会话标识更新；`web/index.html` 与 `web/styles.css` 增加会话标识元素与按钮样式。
- **数据**：澄清轮次从既有会话事件推导，不新增表结构；达到上限的那一轮通过会话服务的追加事件接口补写，避免刷新后消息缺失。
- **风险**：澄清标记依赖模型遵循提示词，需真机验证；若追加事件接口在本项目用法下不可用，则退化为「该轮不入库」，并在 design 的 Open Questions 中记录。
