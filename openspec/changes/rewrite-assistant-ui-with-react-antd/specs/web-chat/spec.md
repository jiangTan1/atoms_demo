# Spec Delta

## MODIFIED Requirements

### Requirement: 界面信息架构

对话界面 SHALL 采用**侧边栏主导的后台布局**：主导航与功能入口（新建会话、历史会话、示例应用、版本、分享、当前用户与账号操作）SHALL 由侧边栏承载，主内容区 SHALL 聚焦「对话 + 应用预览」；顶栏 SHALL 保留品牌标识、当前会话标识与主题切换。窄屏下侧边栏 SHALL 收起并在需要时以可展开的形式提供。

#### Scenario: 侧边栏承载功能入口
- **WHEN** 使用者打开对话界面
- **THEN** 新建会话、历史会话、示例应用、版本、分享与账号相关入口均可从侧边栏或侧边栏内的用户区触达

#### Scenario: 主区聚焦对话与预览
- **WHEN** 使用者在宽屏下使用界面
- **THEN** 主内容区同时呈现对话区与应用预览区，互不遮挡

#### Scenario: 窄屏收起侧边栏
- **WHEN** 使用者在窄屏下使用界面
- **THEN** 侧边栏收起，使用者可通过可展开的形式访问其中的全部入口

#### Scenario: 会话标识常驻
- **WHEN** 使用者处于对话界面
- **THEN** 当前会话标识在顶栏始终可见

### Requirement: 前端实现形态

对话界面 SHALL 以组件化前端工程实现，由构建流程产出静态产物并由服务托管；界面 SHALL NOT 依赖运行时 CDN 获取渲染库。界面与后端之间的接口路径、请求与响应形态（含流式对话的帧类型）SHALL 保持向后兼容，SHALL NOT 因前端实现变化而改变。

#### Scenario: 接口契约不变
- **WHEN** 前端完成迁移后使用者发起对话
- **THEN** 请求路径、请求体与流式帧类型与迁移前一致，后端无需改动

#### Scenario: 不依赖运行时 CDN
- **WHEN** 页面在无法访问外部网络的浏览器中打开
- **THEN** 界面样式、主题与内容渲染仍正常生效

## ADDED Requirements

### Requirement: 迁移后既有交互语义不变

前端实现迁移后，既有交互语义 SHALL 保持不变：流式增量渲染与完整内容兜底、执行进度提示、主动中断、失败重试、401 集中处理、应用预览与刷新、版本列表与回滚、分享链接生成与撤销、示例应用选择即预览、整项目下载、代码块的「复制 / 另存为」操作 SHALL 均可用且行为与迁移前一致。

#### Scenario: 流式与进度
- **WHEN** 使用者发起一轮生成
- **THEN** 内容逐步呈现，并显示执行进度与已用时长，本轮结束后停止更新

#### Scenario: 中断与重试
- **WHEN** 使用者中断长任务，或本轮因超时 / 限流 / 网络异常失败
- **THEN** 中断给出「本轮未完成」的反馈；失败给出中文说明与「重试」入口，重试以同一条消息原样重发

#### Scenario: 预览与版本
- **WHEN** 使用者刷新预览、查看版本或执行回滚
- **THEN** 预览呈现当前沙箱内容；回滚前先留存当前内容为新版本，回滚可逆

#### Scenario: 分享与示例
- **WHEN** 使用者生成分享链接，或选择一个内置示例
- **THEN** 分享链接在未登录状态下可只读预览该版本；选择示例后立即切换到新会话并呈现其预览，无需等待生成

#### Scenario: 登录态失效
- **WHEN** 任一受保护请求返回登录态失效
- **THEN** 界面切回认证界面并提示需要重新登录，不出现未处理的错误或空白页
