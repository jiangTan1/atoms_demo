# Spec Delta

## Purpose

为代码辅助智能体补上文件工具的使用规则：在需要把生成结果落盘时调用文件工具、路径遵循沙箱约定，并确保新增工具不会放宽既有的领域限定与法规安全风险边界。

## ADDED Requirements

### Requirement: 代码辅助智能体装配文件工具
智能体 SHALL 装配沙箱文件工具，以便把生成结果真实写入按会话隔离的沙箱。工具 SHALL NOT 给智能体带来执行外部命令、访问沙箱之外文件或访问网络的能力。

#### Scenario: 生成项目时落盘
- **WHEN** 使用者要求生成一个包含多个文件的项目
- **THEN** 智能体调用文件工具把各文件写入沙箱，并以文本说明目录结构与各文件职责

#### Scenario: 无落盘需求时不调用工具
- **WHEN** 使用者只是提问、解释或排查代码，并未要求产出文件
- **THEN** 智能体直接以文本回答，不调用文件工具

#### Scenario: 能力边界被明确告知
- **WHEN** 使用者要求智能体执行命令、安装依赖或访问沙箱之外的文件
- **THEN** 智能体说明自身不具备该能力，不尝试绕过

### Requirement: 文件工具的调用规范
智能体 SHALL 以相对于沙箱根目录的相对路径调用文件工具，路径 SHALL 与回复中给出的项目结构一致；同一文件的最终内容 SHALL 只写入一次，避免在同一轮内反复覆盖。

#### Scenario: 使用相对路径
- **WHEN** 智能体写入项目文件
- **THEN** 传入的是相对于沙箱根目录的相对路径，且与回复中展示的目录结构一致

#### Scenario: 增量修改已有文件
- **WHEN** 使用者要求修改先前已生成的项目中的某一个文件
- **THEN** 智能体先读取该文件内容，再写入修改后的完整内容，而不是重新生成整个项目

#### Scenario: 不重复写入同一文件
- **WHEN** 智能体在同一轮中调整某个文件的内容
- **THEN** 智能体以最终内容一次写入，不留下多次覆盖的中间状态

### Requirement: 新增工具不改变既有边界
文件工具 SHALL NOT 改变既有的领域范围限定与法规安全风险拒答行为；智能体 SHALL NOT 借助文件工具输出在被拒答情形下本不应给出的内容。

#### Scenario: 领域外请求不落盘
- **WHEN** 使用者提出与代码和编程无关的要求并希望智能体把它写成文件
- **THEN** 智能体按既有固定文案说明领域范围，不调用文件工具

#### Scenario: 法规风险内容不落盘
- **WHEN** 使用者索要涉及漏洞探测或利用的代码并要求写入文件
- **THEN** 智能体按既有拒答规则回复，不把该内容写入沙箱

#### Scenario: 澄清追问仍受次数上限约束
- **WHEN** 智能体为确定项目结构而追问使用者
- **THEN** 该追问仍计入既有澄清轮次并受 5 次上限约束，而工具调用本身不计为一次追问
