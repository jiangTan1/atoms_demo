# Proposal

## Why

当前 Agent 只能把代码"说出来"，不能把文件"写出来"：一次回复里的多个文件各自渲染成代码块，使用者必须逐个点「另存为」（文件名固定为 `snippet.<ext>`、不含任何路径），再自己建目录、改名、归位。这让"帮我生成一个项目"这类请求实际停在半成品状态——模型给了完整的目录结构与各文件内容，但交付环节全靠人工搬运。

## What Changes

- 给 Agent 挂四个文件类工具：`write_file`、`read_file`、`list_files`、`delete_file`，全部限定在按会话隔离的沙箱目录内（`data/workspace/<session_id>/`）。
- 建立沙箱安全边界：拒绝绝对路径与 `..` 片段，写入前校验解析后的真实路径仍位于沙箱内，阻止符号链接逃逸。
- 设置配额上限：单文件字节数、单会话文件数、单会话总字节数，避免一次对话把磁盘写满。
- 新增打包下载接口，并在页面上加「下载整个项目」入口，一键取走该会话已生成的全部文件且保留目录结构。
- **改造现有流式帧的产出方式**：完整帧不再绑定 `partial=False` 事件，改为在事件流结束后统一产出。原因是挂上工具后，一轮对话会出现「文本 → 工具调用 → 更多文本」的交替，`partial=False` 不再等价于「本轮最终回复」（详见 design.md 决策 5）。
- 提示词补充工具使用规则：仅当使用者确实需要文件落盘时才调用、路径一律用相对路径、同一文件不要重复写、不得用工具绕过既有的领域限定与法规风险规则。

## Capabilities

### New Capabilities

- `file-workspace`: 按会话隔离的文件沙箱布局与生命周期、四个文件工具的输入输出契约与错误行为、路径安全与配额边界、打包下载接口的响应契约。

### Modified Capabilities

- `code-assistant-agent`: Agent 装配文件工具，并遵循工具调用规则（何时调用、路径规范、与既有边界规则的关系）。
- `web-chat`: 新增「下载整个项目」入口及其可用状态、失败时的提示行为。

## Impact

- **代码**：`app/agent/`（新增工具模块并装配进 `root_agent`）、`app/services/chat.py`（完整帧产出时机）、`app/api/`（新增打包下载接口）、`app/config.py`（沙箱根目录与配额配置项）、`web/`（下载按钮）。
- **依赖**：不新增第三方依赖，打包用标准库 `zipfile` 生成。
- **数据**：新增 `data/workspace/` 目录，随会话 ID 分目录；该路径已被 `.gitignore` 的 `data/` 覆盖。
- **对外行为**：既有 SSE 帧协议、会话历史与会话 ID 展示保持不变；完整帧的到达时机由「收到最终事件时」变为「事件流结束时」。
- **主要风险**：本功能能否跑通取决于模型是否稳定触发 function call。GLM 系列（当前 `.env` 配置的模型）需真机验证；若不可用则退化为「仅前端打包下载」（见 design.md 的风险与退路）。
