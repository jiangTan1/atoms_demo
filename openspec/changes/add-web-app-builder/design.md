# Design

## Context

动机见 proposal.md 的 Why。本设计基于对当前实现的核实：

- 智能体是 `LlmAgent` **模块级单例**，instruction 是静态文件 `prompts/system.md`；每轮变化的信息（目标语言、澄清轮次）走用户消息前缀注入（`app/services/chat.py` 的 `compose_user_message()`）。
- 四个文件工具（`write_file` / `read_file` / `list_files` / `delete_file`）通过 `tool_context.session.id` 拿到会话标识，落到 `data/workspace/<会话>/`（`app/services/workspace.py`）。沙箱已有路径安全（拒绝绝对路径、`..`、符号链接逃逸）与三项配额（单文件 256 KB、200 个文件、10 MB）。
- 会话与沙箱归属由登录态决定：`user_id = "user:<用户名>"`，四个既有接口都声明了 `Depends(current_user)`。
- AI 回复的三层归一化（ADK Event → 服务层 Frame → SSE 文本）已稳定；**完整帧在事件循环结束后由累积文本产出一次**（`app/services/chat.py`），这是本轮「流结束后做快照」的天然挂点。
- 前端是无构建的单页 `web/index.html` + `web/app.js`，已有认证门控、顶栏（会话 ID、当前用户、修改密码、退出、下载整个项目）与弹层（改密）三处可复用的形态。
- 前端**没有任何服务端渲染/预览能力**，产物只能整包下载。
- 项目现状：`SESSION_BACKEND=sqlite` 落 `data/sessions.db`；账号库独立为 `data/users.db`；`data/` 已在 `.gitignore` 内。

## Goals / Non-Goals

**Goals:**

- 产物语义明确：沙箱里放的就是一个能跑的网页应用（含入口 `index.html`），而不是一堆源码。
- 预览与主站运行环境隔离：执行的是模型生成的脚本，不能读登录态、不能代表使用者调用接口。
- 版本可追、可退、可逆：每轮自动快照，回滚不销毁历史。
- 分享只读且不可枚举：拿到链接即可看，但拿不走别的。

**Non-Goals:**

- 不引入构建工具链（npm / 打包器）与前端框架版本管理：生成的应用必须是「打开 `index.html` 就能跑」的静态产物。
- 不做独立的预览域名或独立端口：本版靠 iframe 沙箱属性达成隔离，跨源隔离列入后续（见 Open Questions）。
- 不做多人协作、评论、应用市场与画廊。
- 不改 ADK 层与会话落盘结构（`sessions.db` 不动）。
- 不做应用的 SEO/服务端渲染，也不对外提供稳定的生产域名。

## Decisions

### 1. 产物形态：多文件 + 入口 `index.html`，资源一律相对路径

- **做法**：约定沙箱内必须存在 `index.html`；样式、脚本、图片放在沙箱内的相对路径下并由入口以相对路径引用；不引入构建步骤与外部依赖安装。提示词据此改写（见决策 7）。
- **理由**：多文件才符合「网页应用」的工程直觉（HTML/CSS/JS 分离），也沿用既有的文件工具与配额；而只要「入口固定 + 引用用相对路径」，预览就能用一个静态路由整目录提供，无需改写任何路径。
- **备选**：单文件 HTML（被排除：使用者已明确选择多文件）；引入打包步骤（被排除：与「无构建」的既有取向冲突，且配额与沙箱都按静态文件设计）。
- **连带结论**：既有硬约束「网页实现按语言拆分代码块」被本次变更取代——产物从「回复中的代码块」变成「沙箱内的应用文件」。

### 2. 预览：把会话沙箱目录当作静态站点挂在预览路由下

- **做法**：新增预览路由（形如 `/preview/<会话标识>/<资源相对路径>`），根路径返回该会话的入口 `index.html`，其余路径按相对路径在沙箱内取文件，并按扩展名给出正确的 `Content-Type`；响应统一加 `X-Content-Type-Options: nosniff`。前端用 iframe 指向该地址。
- **理由**：`/style.css` 与 `/app.js` 能否解析取决于**路径空间**，只要把沙箱挂成一个站点的根，相对引用就自然成立，生成端与被预览端都不需要知道对方的存在。顺带复用了沙箱已有的路径安全校验（`resolve()` 后判定仍在沙箱内）。
- **备选**：把 `index.html` 内容读出来用 `srcdoc` 或 Blob URL 注入（被排除：相对路径的资源全部失效，多文件形态直接不成立）；前端把文件内容拼成一个 Data URL（被排除：同上，且体积与转义都不可控）。

### 3. 预览隔离：同源路由 + iframe 沙箱属性（不给 `allow-same-origin`）

- **做法**：预览 iframe 使用 `sandbox` 属性并**只授予**运行所需的能力（`allow-scripts`、`allow-forms`、`allow-modals`、`allow-popups`、`allow-pointer-lock`），**不授予** `allow-same-origin`，也**不授予** `allow-top-navigation`。同时预览响应加 CSP，限制其只能加载自身所需资源。
- **理由**：不给 `allow-same-origin` 会让预览文档处在**不透明源**中——脚本能跑，但 `document.cookie`、`localStorage` 一律不可用，向主站接口发起的 `fetch` 也是跨源且不带凭据，因而拿不到登录态、也无法代表使用者操作。`allow-scripts` 与 `allow-same-origin` 同时授予会让沙箱形同虚设（脚本可自行移除 sandbox 属性），因此两者**绝不同时给**。
- **备选**：把预览挂到独立域名或独立端口（被排除：本版不改部署形态，且 Nginx 与证书都要跟着改；作为后续强化项保留）；不做隔离直接同源同文档渲染（被排除：等于让模型生成的脚本在主站上下文里执行，可以直接读 Cookie 并调用管理接口）。

### 4. 版本：文件系统快照目录，而不是 git

- **做法**：单会话的版本存为 `data/versions/<会话标识>/<版本标识>/`，版本标识用单调递增的序号或时间戳；每个版本目录是该会话沙箱内容的一次**完整复制**。是否产生新版本由「本轮结束后沙箱指纹是否变化」判定（文件清单 + 各文件大小/哈希），未变化则不产生新版本。单会话版本数设上限（如 20），超出按最旧优先清理。
- **理由**：快照就是「拷一份目录」，标准库 `shutil.copytree` 即可完成，无新依赖、无外部进程、语义直观；配额已经把单会话规模压在 10 MB 级，拷一份的成本可以接受。而引入 git 会把「版本」绑到仓库语义上（分支、提交对象、二进制文件、`.git` 体积），对这个场景是明显的过度设计。
- **备选**：git 仓库按会话初始化、每轮 `commit`（被排除：重、需依赖外部或第三方库、回滚还要处理工作区与分支）；把每轮的**文件差异**存成 patch（被排除：合并与冲突逻辑会迅速超过本场景所需，且模型可能整文件重写导致 patch 意义有限）；只存数据库里的文件内容行（被排除：与既有「沙箱就是目录」的事实存储两套真相，容易不一致）。

### 5. 回滚：先留存再整体替换，保证可逆

- **做法**：回滚时先把**当前**沙箱内容留成一份快照（例如记为「回滚前」版本），再用目标版本的内容整体重建沙箱（先清空沙箱内文件，再从快照目录复制回来）。被跨过的版本一律保留在列表中。
- **理由**：spec 要求「回滚可逆且不回退历史」。若回滚直接覆盖沙箱，使用者一失手就回不到回滚前的状态；先留存再替换，使「回滚」本身也是一次有痕操作，符合「每轮留档」的一贯语义。
- **备选**：回滚时直接把目标版本复制进沙箱、不保留当前内容（被排除：不可逆，误操作代价高）。

### 6. 分享：独立 `data/shares.db` + 指向**版本快照**的只读路由

- **做法**：新增独立库 `data/shares.db`（标准库 `sqlite3`，与 `users.db`、`sessions.db` 解耦），记录 `token`、`会话标识`、`版本标识`、`创建者`、`创建时间`。`token` 用 `secrets.token_urlsafe(32)` 生成，作为链接中的不可枚举标识。分享路由免登录、只读，**内容取自被分享的那个版本快照**而不是当前沙箱。撤销即删除记录。
- **理由**：分享指向**版本**而非「当前沙箱」有两个好处：一是链接内容稳定，使用者后续继续改应用不会把已发出去的链接内容悄悄改掉；二是分享不需要读会话（也就不会牵扯 ADK 的会话查询与归属逻辑），只读快照目录即可，实现面最小。独立库的理由与账号库一致：分享数据的持久化不应随 `SESSION_BACKEND` 变化，也不要和 ADK 持有的 schema 混在一起。
- **备选**：分享指向当前沙箱（被排除：链接内容会随后续对话漂移，「分享出去的东西被改了」是使用者的常见惊讶点）；把分享记录写进 `sessions.db`（被排除：与 ADK 持有的 schema 耦合）；把分享做成长期存在的静态副本再单独托管（被排除：本版不引入静态托管）。

### 7. 智能体定位与提示词重写

- **做法**：重写 `prompts/system.md`——人设从「面向开发者的代码助手」改为「网页应用生成智能体」；任务从四类（生成/解释/重构/排查）收窄为「生成应用 / 迭代修改应用」；保留既有的法规与安全风险拒答、澄清追问与次数上限机制（它们与定位无关，且已有 spec 与测试覆盖）；新增「产物约定」（入口文件、相对路径、不依赖沙箱外资源）与「如实说明应用能力」。范围外的固定回复文案随之替换。
- **理由**：instruction 是静态单例，改定位就是改这一个文件，落地成本最低；而澄清轮次与法规边界是**服务端也参与的机制**（`count_clarify_rounds()`、`[[CLARIFY]]` 标记），保留它们可以不动服务层与既有测试。
- **备选**：新增一个独立 Agent 与工具集、按会话选择（被排除：本版只有一种定位，多 Agent 只会增加装配复杂度）；保留四类任务、把网页应用作为第五类（被排除：使用者已明确选择收窄，定位混杂会让意图识别与提示词都变复杂）。

### 8. 快照的触发点：流结束后比对沙箱指纹，不侵入 ADK

- **做法**：在对话流正常结束、准备产出完整帧的位置（`app/services/chat.py` 的收尾处，由接口层驱动）比对会话沙箱的指纹：与本会话「上次快照时的指纹」不同则生成新版本。指纹存在服务端（内存 + 落盘的小索引），不放会话 `state`。
- **理由**：`is_final_response()` 与 `partial` 在挂上工具后已不可靠（既有设计已把完整帧移到流结束后），因此「本轮是否改动沙箱」同样应该在流结束后用**可观测的事实**（沙箱内容）判定，而不是猜事件语义。用指纹比对而不是「本轮是否调用过 write_file」还能覆盖删除、覆盖为空等情形。
- **备选**：在文件工具内部每次写入就快照（被排除：一轮里模型可能多次覆盖同一文件，会产生大量中间版本）；在 ADK 的 `after_agent_callback` 里做（被排除：要理解并绑定 ADK 的生命周期语义，且拿不到「流已结束」这个收尾点）。

### 9. 前端：左对话右预览，版本与分享复用既有的顶栏与弹层

- **做法**：`index.html` 在对话区右侧增加预览面板（iframe + 刷新按钮 + 状态提示）；顶栏新增「版本」与「分享」两个入口，各自复用既有 `.modal` 弹层形态：版本弹层列出历史版本并可回滚；分享弹层可对某版本生成链接、列出自己已创建的分享并撤销。预览地址按当前会话构造（`/preview/<会话标识>/`）。
- **理由**：既有的弹层、按钮、提示样式都已沉淀并踩过 `hidden` 与 `display` 的坑，复用比新造一套更稳；预览用 iframe 是唯一能同时满足「多文件相对路径」与「隔离」的做法。
- **备选**：把预览做成独立页面/新标签页打开（被排除：与「对话中改一版看一版」的主流程割裂，且要跨页同步会话状态）；在对话流里内联渲染应用（被排除：无法隔离，且与消息流渲染冲突）。

### 10. 版本与分享的存储位置与配额口径

| 项 | 位置 / 取值 |
| --- | --- |
| 版本快照 | `data/versions/<会话标识>/<版本标识>/` |
| 分享记录 | `data/shares.db`（表含 `token`、`session_id`、`version_id`、`created_by`、`created_at`） |
| 单会话版本上限 | 20（超出按最旧清理） |
| 分享 token | `secrets.token_urlsafe(32)` |

- **理由**：三份数据各归其位——会话在 `sessions.db`（ADK 持有）、账号在 `users.db`、版本是文件、分享在 `shares.db`；任一份出问题都不会连带另一份。版本上限与沙箱配额一样做成可配置项（走既有 `_positive_int()` 约定），便于上线后调节。
- **连带结论**：`data/versions` 与 `data/shares.db` 都在 `data/` 之下，已被 `.gitignore` 覆盖，无需改忽略规则。

## Risks / Trade-offs

- [预览执行的是模型生成的脚本，隔离失效即等于主站被接管] → 预览 iframe 绝不同时授予 `allow-scripts` 与 `allow-same-origin`，不给 `allow-top-navigation`；预览响应加 `nosniff` 与 CSP；预览路由只服务沙箱内文件且复用既有路径逃逸校验；把「独立源（域名/端口）」列入 Open Questions 作为进一步强化。
- [不透明源下 `localStorage` 与同源 `fetch` 不可用，部分应用写法会失效] → 提示词要求应用不依赖持久化与网络；预览区在加载失败时给出可理解提示，并把该限制写入文档与已知限制。
- [版本快照是整目录复制，磁盘占用随会话数与版本数增长] → 单会话沙箱已有 10 MB 上限，叠加单会话版本上限 20，单会话上界约 200 MB 且可配置；配合 P0 既有的「沙箱清理」缺口一并纳入运维提示。
- [「流结束后比对指纹」需要一个跨请求保存的指纹状态] → 指纹随会话存于服务端小索引（可落 `data/` 下），丢失只会导致多存一个版本，不影响正确性；不写入 ADK 的会话 `state`，避免与 ADK 语义耦合。
- [分享免登录，等于开了一个无鉴权的读入口] → token 随机且不可枚举；分享只读、只指向某个版本快照、不暴露会话标识与历史；沿用 Nginx 的按来源 IP 限流；撤销即时生效。
- [BREAKING：既有沙箱内容没有 `index.html`，旧会话无法预览] → 属有意行为，proposal 已声明；预览区对「缺少入口文件」给出明确提示而非报错，旧内容仍可打包下载。
- [提示词约束「不依赖沙箱外资源」是软约束，模型仍可能引用 CDN] → 沙箱外的 CDN 在预览中通常仍可加载，因此不是硬失败；如实说明与已知限制中记录该偏差，不做服务端强制改写。
- [定位收窄会让既有用户失去通用问答能力] → 属使用者明确决策；proposal 的 REMOVED 说明中保留了「改为提出网页应用需求」的迁移路径。

## Migration Plan

1. 提示词与定位：重写 `prompts/system.md`（人设、任务、产物约定、范围外固定文案），保留法规边界与澄清机制。
2. 沙箱能力扩展：在 `app/services/workspace.py` 增加「入口文件定位」「按相对路径取单个文件（含内容类型判定）」「快照 / 恢复」三组能力，复用既有路径安全与配额校验。
3. 版本服务：新增 `app/services/versions.py`（快照创建、指纹比对、列表、回滚、按上限清理）与对应接口。
4. 预览路由：新增预览接口（会话内预览需登录且校验归属；分享预览免登录）。
5. 分享服务：新增 `data/shares.db` 与 `app/services/shares.py`（创建、列出、撤销、按 token 解析到版本快照）。
6. 对话收尾挂点：在流结束后比对指纹并按需生成版本。
7. 前端：预览面板、版本弹层、分享弹层；预览区状态反馈；401 沿用既有集中处理。
8. 测试与验收：单元测试覆盖快照/回滚可逆、指纹不误判、分享只读与撤销、预览归属与逃逸拒绝；端到端验收「描述需求→生成→预览→改功能→回滚→分享给未登录访问者」。

回滚：本变更集中在提示词、`workspace.py` 的扩展、新增的版本/分享/预览服务与路由、以及前端三处交互。回退时删除新增服务与路由、恢复 `prompts/system.md` 即可回到「代码助手 + 打包下载」形态；`data/versions/` 与 `data/shares.db` 为独立数据，删除不影响既有会话与账号。

## Open Questions

- 是否把预览迁到独立源（独立域名或独立端口）以获得浏览器级的同源隔离——取决于部署形态，本版不动部署，先靠 iframe 沙箱属性，待有公网部署需求时再评估。
- 单会话版本上限取 20 是否合适、是否需要「锁定版本不参与清理」——先用默认值观察实际使用，必要时再调。
- 分享是否需要有效期与访问计数——本版只做创建/撤销，按需再加。
