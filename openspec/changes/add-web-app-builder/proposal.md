# Proposal

## Why

当前智能体的定位是「通用代码助手」：它按四类任务（生成 / 解释 / 重构 / 缺陷排查）输出代码块，把文件写进沙箱后只能整包下载——使用者拿到的是**源码**，不是**能跑的东西**，做完也不知道对不对，改一版就丢了上一版。

把这个 demo 的目标收窄为「对话式网页应用生成器」：需求 → 生成可运行的多文件网页应用 → **页面内直接预览** → 继续用对话改功能 → 每轮自动留版本、可回滚 → 生成链接分享。这条链路才是「用对话做出一个网页应用」的完整闭环，也让此前的沙箱、会话、鉴权等既有能力第一次有了真正的落点。

## What Changes

- **智能体定位收窄**：从「四类代码任务」改为「只做网页应用」。`prompts/system.md` 重写为网页应用生成器的人设、任务与边界；领域外固定回复文案随之改变。
- **产物形态约定为可直接运行的多文件网页应用**：沙箱内必须有入口文件 `index.html`，配套的样式与脚本以相对路径引用，浏览器打开入口即可运行。
- **新增应用预览**：新增预览路由，把某会话沙箱目录作为静态站点对外提供，前端以 iframe 呈现，使用者无需下载即可看到并操作应用。
- **新增版本快照与回滚**：每轮智能体修改后自动存一个快照；界面给出**版本列表**，可把沙箱恢复到此前的任意版本。回滚本身也留痕，保证可再次回滚回去。
- **新增公开只读分享**：为某个版本生成分享令牌，任何人凭链接即可打开预览，无需登录，且只能看不能对话、不能改。
- **BREAKING**：不再支持通用代码问答（代码解释、重构、缺陷排查）与「只输出代码块、不落盘」的作答方式；沙箱内没有 `index.html` 的既有会话无法预览。

## Capabilities

### New Capabilities

- `web-app-preview`: 把会话沙箱作为静态站点对外提供预览，并把预览运行环境与主站隔离，使生成的代码可以运行但不能触碰登录态、不能导航主站。
- `app-versions`: 每轮自动快照会话沙箱、列出与查看版本、把沙箱恢复到指定版本，并保证回滚可逆。
- `app-sharing`: 为某个版本生成公开只读的分享链接，免登录查看、不可对话与修改。

### Modified Capabilities

- `code-assistant-agent`: 智能体职责由「四类代码任务」收窄为「生成与迭代网页应用」；领域边界固定回复文案随之调整。
- `web-chat`: 对话界面由「只有对话区」扩展为「对话区 + 预览区」，并新增版本列表与回滚、分享入口。
- `file-workspace`: 沙箱产物的语义由「任意代码文件」明确为「可直接运行的网页应用（含入口 `index.html`）」，并新增快照与恢复所依赖的沙箱复制能力边界。

## Impact

- **代码**：`prompts/system.md` 重写；新增 `app/services/preview.py`、`app/services/versions.py`、`app/services/shares.py` 与对应 `app/api/` 路由；`app/services/workspace.py` 扩展快照/恢复/入口文件解析；`web/index.html`、`web/styles.css`、`web/app.js` 增加预览区、版本列表与分享交互；`app/main.py` 挂载新路由。
- **接口**：新增预览、版本列表 / 回滚、分享创建 / 访问等接口；既有 `/api/chat`、`/api/sessions`、`/api/workspace/download` 保持兼容，但对话产出的语义改变。
- **数据**：新增 `data/versions/<会话>/` 快照目录与 `data/shares.db`（或等价存储）；`data/` 已在 `.gitignore` 内，不进入版本控制。
- **安全**：预览将执行使用者生成（且由模型产出）的 JavaScript，必须有明确的运行隔离与来源限制，详见 design.md。
- **文档**：`README.md` 与 `docs/project-overview.md` 的项目定位、能力清单与已知限制需同步更新。
