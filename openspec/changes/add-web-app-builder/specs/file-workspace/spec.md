# Spec Delta

## ADDED Requirements

### Requirement: 沙箱内容的快照与恢复
系统 SHALL 支持把会话沙箱的全部内容复制为一份独立快照，并支持用某份快照覆盖式重建该会话的沙箱内容。快照 SHALL 是独立副本，其内容 SHALL NOT 随沙箱后续的改动而变化。

#### Scenario: 快照与沙箱后续改动解耦
- **WHEN** 某会话对沙箱做了一份快照，随后智能体又改写了沙箱内的文件
- **THEN** 该快照的内容仍为此前那一刻的内容，不被后续改动影响

#### Scenario: 用快照重建沙箱
- **WHEN** 使用者要求恢复到某份快照
- **THEN** 该会话沙箱的内容被重建为该快照的内容，与快照不一致的文件不再存在于沙箱内

#### Scenario: 恢复前的沙箱内容被保留
- **WHEN** 系统执行一次恢复
- **THEN** 恢复前的沙箱内容被另行留存为一份快照，可用于再次恢复

#### Scenario: 快照不越出沙箱
- **WHEN** 系统为某会话创建或恢复快照
- **THEN** 操作只作用于该会话自己的沙箱与快照，其他会话的沙箱与快照不受影响

### Requirement: 应用入口文件的定位
系统 SHALL 能够判定会话沙箱内是否存在应用入口文件 `index.html`，并在存在时定位该文件；该判定 SHALL 基于沙箱内的真实文件，而不是固定假定应用结构。

#### Scenario: 存在入口文件
- **WHEN** 沙箱内存在 `index.html`
- **THEN** 系统能够识别并定位到该入口文件

#### Scenario: 缺少入口文件
- **WHEN** 沙箱内不存在 `index.html`
- **THEN** 系统判定该会话尚无可用入口，并据此给出缺少入口的提示

#### Scenario: 沙箱为空
- **WHEN** 沙箱内没有任何文件
- **THEN** 系统判定该会话尚无内容，并据此给出尚无应用的提示

### Requirement: 沙箱资源按路径空间提供
系统 SHALL 能够按沙箱内相对路径取用单个文件，使预览可以像静态站点一样提供入口页面及其相对引用的资源；该取用 SHALL 拒绝任何逃出沙箱的路径。

#### Scenario: 取用入口页面
- **WHEN** 预览请求沙箱根下的入口页面路径
- **THEN** 系统返回该文件内容及其对应的内容类型

#### Scenario: 取用子目录资源
- **WHEN** 预览请求沙箱内子目录下的样式或脚本
- **THEN** 系统返回该文件内容及其对应的内容类型

#### Scenario: 拒绝逃逸路径
- **WHEN** 请求的路径为绝对路径、含 `..` 或经符号链接指向沙箱之外
- **THEN** 系统拒绝该请求，沙箱外文件不被读取
