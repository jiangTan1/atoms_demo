# Spec Delta

## ADDED Requirements

### Requirement: 网页应用生成
智能体 SHALL 根据使用者的自然语言描述生成一个可直接运行的网页应用，并把构成该应用的全部文件写入当前会话沙箱；生成结果 SHALL 可在浏览器中直接运行，无需安装依赖或构建步骤。

#### Scenario: 描述需求即生成应用
- **WHEN** 使用者描述想要的应用（如「做一个俄罗斯方块小游戏」）
- **THEN** 智能体把该应用的文件写入沙箱，并说明它做了什么、如何操作

#### Scenario: 应用可直接运行
- **WHEN** 使用者预览刚生成的应用
- **THEN** 应用无需下载依赖或执行构建即可运行，界面与交互生效

#### Scenario: 需求信息不足
- **WHEN** 使用者的描述缺少实现所必需的关键信息（如玩法规则未定）
- **THEN** 智能体先提出澄清性问题或列出一个合理的默认方案再生成

### Requirement: 应用产物约定
生成的应用 SHALL 包含入口文件 `index.html`；页面引用的样式、脚本与其他资源 SHALL 使用相对路径放在沙箱内，使整个应用在沙箱目录这一路径空间下即可运行。

#### Scenario: 入口文件存在
- **WHEN** 智能体为某会话生成或修改应用
- **THEN** 沙箱内存在入口文件 `index.html`

#### Scenario: 资源以相对路径引用
- **WHEN** 应用包含独立的样式表或脚本
- **THEN** 入口页面以相对路径引用它们，且这些文件位于沙箱内被引用到的位置

#### Scenario: 不引用沙箱外资源
- **WHEN** 生成的应用需要样式或脚本
- **THEN** 这些资源落在会话沙箱内，不依赖沙箱之外的文件才能运行

### Requirement: 对话式迭代修改
使用者要求修改或新增功能时，智能体 SHALL 基于沙箱内该应用的当前内容做增量修改，保留使用者未要求改动的部分；SHALL NOT 无视既有内容重新生成一个不相关的新应用。

#### Scenario: 修改既有应用
- **WHEN** 使用者在已生成应用的会话中提出新的修改需求（如「把下落速度调快一点」「加一个计分板」）
- **THEN** 智能体在既有应用的基础上修改相关文件，其余功能保持可用

#### Scenario: 新增功能
- **WHEN** 使用者要求为既有应用新增一项功能
- **THEN** 智能体在既有应用上添加该功能，原有交互不被破坏

#### Scenario: 先查看再修改
- **WHEN** 智能体需要修改一个此前生成的文件
- **THEN** 智能体先读取该文件的现有内容再写入修改后的完整内容，不凭记忆重写整个应用

### Requirement: 职责范围与固定回复
智能体 SHALL 只处理网页应用相关的问题：把使用者的自然语言需求实现为一个可直接运行的网页应用；当判定使用者输入与网页应用无关时，SHALL 不尝试作答，并 SHALL 以固定文案回复：「我是一个网页应用生成智能体，只能根据需求生成和修改网页应用。请描述你想要的网页应用，比如"做一个俄罗斯方块小游戏"。」

#### Scenario: 范围外提问
- **WHEN** 使用者提出与网页应用无关的问题（如闲聊、生活咨询、其他专业领域问题）
- **THEN** 智能体不回答该问题本身，仅按固定文案说明自己的范围并邀请使用者描述想要的网页应用

#### Scenario: 范围内提问不触发该回复
- **WHEN** 使用者描述一个想要的网页应用或要求修改已有应用
- **THEN** 智能体正常执行任务，不输出上述固定文案

#### Scenario: 边界模糊的提问
- **WHEN** 使用者的输入表面与网页应用无关，但可合理理解为想做一个网页应用（如「我想做个能算账的东西」）
- **THEN** 智能体按网页应用需求处理或先做澄清，而不是直接按范围外拒答

### Requirement: 使用说明与应用自身能力
智能体 SHALL 在回复中用自然语言说明本次产出的应用做了什么、如何操作、有哪些已知限制；SHALL NOT 声称应用具备它实际没有的能力（如保存到服务器、访问网络、读取本地文件）。

#### Scenario: 说明应用功能与操作
- **WHEN** 智能体生成或修改了应用
- **THEN** 回复中说明该应用的功能与操作方式，内容与沙箱内的实现一致

#### Scenario: 不夸大能力
- **WHEN** 使用者询问应用是否具备某项沙箱之外的能力（如联网、持久化到服务器）
- **THEN** 智能体如实说明不具备该能力，不编造或假装已实现

#### Scenario: 内容仍受既有边界约束
- **WHEN** 使用者的需求涉及法规与安全风险内容
- **THEN** 智能体按既有边界规则拒答，且不把该类内容写入沙箱
