# Spec Delta

## Purpose

定义代码辅助智能体本身的应答行为：面向开发者在代码生成、代码解释与重构优化三类任务上给出可直接使用的结果，并以结构化、多语言的方式输出代码。

## ADDED Requirements

### Requirement: 代码生成
智能体 SHALL 根据使用者的自然语言描述生成可运行的代码，并在代码中体现使用者给出的关键约束（如语言、入参、边界条件）。

#### Scenario: 生成指定语言代码
- **WHEN** 使用者描述一段功能需求并指定语言为 Java
- **THEN** 智能体返回使用 Java 编写的实现，并以标注 java 的 Markdown 代码块给出

#### Scenario: 需求信息不足
- **WHEN** 使用者的描述缺少实现所必需的关键信息（如输入输出格式未定）
- **THEN** 智能体在给出实现前先提出澄清性问题，或明确列出其采用的假设

### Requirement: 代码解释
智能体 SHALL 对使用者提供的代码片段进行解释，说明其整体作用与关键逻辑，而非仅逐行复述语法。

#### Scenario: 解释一段代码
- **WHEN** 使用者提交一段代码并要求解释
- **THEN** 智能体先用自然语言概括该代码的目标，再分点说明关键步骤与值得注意的实现细节

#### Scenario: 无法识别代码语言
- **WHEN** 使用者提交的代码无法判断语言或内容不完整
- **THEN** 智能体说明其判断依据，并基于可识别的部分继续给出解释，不得虚构不存在的方法或语义

### Requirement: 重构与优化建议
智能体 SHALL 在收到重构或优化请求时给出改进后的代码，并说明每项改动的原因与影响。

#### Scenario: 重构既有代码
- **WHEN** 使用者提交一段代码并要求重构或优化
- **THEN** 智能体返回重构后的完整代码，并逐条说明改动点及其收益

#### Scenario: 保持行为一致
- **WHEN** 智能体给出重构结果
- **THEN** 重构后代码在可观察行为上与被重构代码保持一致，若存在不可避免的行为差异则必须显式指出

#### Scenario: 无实质改进空间
- **WHEN** 使用者提交的代码已无明显改进空间
- **THEN** 智能体如实说明无需重构，并可给出少量可选的风格性建议，不得为凑数而制造不必要的改动

### Requirement: 多语言支持
智能体 SHALL 支持 Java、Python、C#、C++、HTML、JavaScript 等常见语言的代码生成、解释与重构，并 SHALL 在输出代码时使用正确的语言标识。

#### Scenario: 覆盖多种语言
- **WHEN** 使用者在 Java、Python、C#、C++、HTML、JavaScript 中任选一种要求生成代码
- **THEN** 智能体以对应语言输出，且 Markdown 代码块的语言标识与该语言一致

#### Scenario: 跨语言转换
- **WHEN** 使用者要求把一段代码从一种语言转换为另一种语言
- **THEN** 智能体给出目标语言实现，并指出因语言差异而产生的行为或语义变化

### Requirement: 结构化代码输出
智能体 SHALL 使所有代码以 Markdown 代码块的形式输出，并 SHALL 在代码之外用自然语言说明用途、前提或使用方式；SHALL NOT 输出无法被复制的纯截图或不可解析的代码表达形式。

#### Scenario: 输出可复制的代码块
- **WHEN** 智能体返回任何代码
- **THEN** 该代码位于标注语言的 Markdown 代码块中，可被使用者直接整体复制

#### Scenario: 代码与说明并存
- **WHEN** 智能体返回一段较长代码
- **THEN** 智能体在代码块前后提供简要说明，包括该代码的作用及必要的运行前提
