# Spec Delta

## Purpose

为使用者提供一个基于网页的多轮代码辅助对话入口：以流式方式呈现智能体回答，并把回答中的代码片段及其所用语言清晰地展示出来，便于阅读与复用。

## ADDED Requirements

### Requirement: 网页对话入口
系统 SHALL 提供一个网页界面，使用者可在其中输入自然语言问题并获得智能体的回复，界面在服务启动后可通过浏览器直接访问，无需前端构建步骤。

#### Scenario: 打开对话页面
- **WHEN** 使用者在浏览器访问服务根路径
- **THEN** 系统返回对话页面，页面包含消息列表区域、输入框与发送按钮

#### Scenario: 提交一次提问
- **WHEN** 使用者在输入框填写内容并触发发送
- **THEN** 系统将该内容作为用户消息展示在消息列表中，并向服务端发起对话请求

### Requirement: 流式增量展示
系统 SHALL 在智能体生成回复的过程中以流式方式增量更新页面内容，而非等待整段回复完成后一次性显示。

#### Scenario: 回复逐步出现
- **WHEN** 服务端开始返回增量文本片段
- **THEN** 页面在同一回复气泡内持续追加内容，直到该轮回复结束

#### Scenario: 流式连接异常
- **WHEN** 流式连接在回复完成前中断或服务端返回错误
- **THEN** 页面保留已接收的内容，并展示可识别的错误提示，且允许使用者重新发送

### Requirement: 代码片段展示
系统 SHALL 将回复中的 Markdown 代码块渲染为带语法高亮的代码区域，并标注该代码块所使用的语言。

#### Scenario: 渲染带语言标识的代码块
- **WHEN** 回复中出现标注了语言的 Markdown 代码块
- **THEN** 页面以等宽字体、语法高亮形式展示该代码，并显示对应的语言名称

#### Scenario: 渲染未标注语言的代码块
- **WHEN** 回复中出现未标注语言的代码块
- **THEN** 页面仍以等宽字体代码区域展示，语言标识显示为通用或纯文本，不得出现渲染错误

#### Scenario: 复制代码
- **WHEN** 使用者点击代码区域上的复制操作
- **THEN** 系统将该代码块的纯文本内容复制到剪贴板，并给出复制成功或失败的反馈

### Requirement: 多轮会话管理
系统 SHALL 为每个使用者维护相互独立的多轮会话，使后续提问能够利用同一会话内的历史上下文；使用者 SHALL 能够新建会话以开始无历史的对话。

#### Scenario: 同一会话内追问
- **WHEN** 使用者在同一会话中连续提出相关联的问题
- **THEN** 智能体的回复体现对前序对话内容的利用

#### Scenario: 新建会话
- **WHEN** 使用者触发新建会话
- **THEN** 页面清空当前消息列表，且后续提问不携带此前的对话历史

### Requirement: 目标语言选择
系统 SHALL 允许使用者选择期望的代码输出语言，选项至少覆盖 Java、Python、C#、C++、HTML、JavaScript。

#### Scenario: 指定输出语言
- **WHEN** 使用者选择某一目标语言后提交代码生成类问题
- **THEN** 智能体以该语言给出代码实现

#### Scenario: 选择网页相关语言
- **WHEN** 使用者选择 HTML 或 JavaScript 后提交网页实现类问题
- **THEN** 智能体分别以标注 html 与 javascript 的代码块给出结构与脚本，且代码块语言标识与选择一致

#### Scenario: 未指定输出语言
- **WHEN** 使用者未选择目标语言
- **THEN** 系统按问题语义自行推断合适的语言，或在语义不足以确定时向使用者澄清
